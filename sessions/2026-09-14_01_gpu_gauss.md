# GPU Gauss6차 구현과 독립 검산

## 현재 상태

- 후속 타임스텝 탐색 완료: 동일 두 국소 상태에서 Newmark/GPU Gauss24개 lane의 풀이·GPU 검산 비용과 인접 시간 분할 차이를 대조했다. 집계기의 검산 태그 선택과 전용 그림 스크립트를 추가했다. 속도 최소와 teacher 정확도를 분리하며 기본 솔버/API는 유지한다. [결과](../../experiments/R1_teacher_velocity_reset/timestep_search/cloth_coarse/gauss_timestep_sweep.md).
- 확인일2026-09-14. 사용자 요청의 Gauss6차 GPU 상주 구현과 기존 솔버/세분 Newmark/CPU Gauss 비교를 완료했다. 기본 Newmark/FP64 hi/lo와 학습 Gate는 유지한다.
- 3개 내부 상태의 Newton/GMRES/line search, 실수 단계 결합 보조 행렬의 GPU 구축·cuDSS 분해·재사용, raw hi/lo 갱신을 별도 객체로 구현했다. 기존 물리식은 변경하지 않았다.
- 별도 GPU buffer에서 단계 힘/갱신/에너지·P3×cubic 국소 기하를 재검산한다. CPU longdouble 원식 대조와 손상 가속도/에너지/NaN의 거부, 계산/검산의 host 조회 부재를 확인했다.
- 관련4개 회귀 검사 통과. 실제두 seed의 짧은 구간·16개 완료 lane 및 Gauss64개 고유 substep 검산 근거는 [실험 보고서](../../experiments/R1_teacher_velocity_reset/timestep_search/cloth_coarse/gauss_gpu_comparison.md)가 소유한다.
- Gauss16분할은 다음 검증 후보이며 전체 시간/공간 수렴·장기 실행기/checkpoint 연결·접촉·학습 적격성은 미완료다. 재사용64를 보편적 정책으로 채택하지 않았다.
- 큰 행렬 capture는 기존 workspace shim이 필요하다. 수치 재현성을 bitwise 동일성과 혼동하지 않는다. 구현과 buffer/cache/검산 계약은 [상세 문서](../docs/gpu_gauss_solver.md)를 따른다.
- R1 구현 계약에도 반영했다. 원본 보존, 외부 fetch/다운로드·stage·commit·push 없음.
