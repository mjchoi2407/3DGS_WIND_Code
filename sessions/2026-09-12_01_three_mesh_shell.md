# 세 메시 P3 연결과 장기 실행 준비

## 현재 상태

**최신 v4 준비:** 사용자 승인으로 세 씬의 이후 모든 프레임에64회 재구축을 적용했다. 첫 씬364frame/6.0667초 보존 재개, 추가 두 씬0초부터·시간 제한 없음. CPU7개 및 세 씬 각64step GPU검산 통과. 본 계산 미시작. [실행·설정 경계·한계](../../experiments/R1_teacher_velocity_reset/timestep_search/evidence/reuse64_batch_20260912/README.md). 아래 선택 대기는 해소됐다.

**최신 복구(2026-09-12):** v2 첫 씬은6.0667초에서4시간 한도 종료, 추가 두 씬은 Python 빌드 문자열 검사로 시작 전 종료했다.
사용자 요청으로 빌드 날짜를 호환성 키에서 제외하고 버전·구현·ABI·아키텍처·수치 라이브러리는 검증한다.
v3는 세 씬 모두 시간 한도 없음. 기존364frame의 hash 검증·독립 복사 후 첫 씬 재개, 나머지는0초부터 준비했다.
CPU6개 검사·새 환경의 세 씬 각64step 재계산 통과, 기존 경로 차이0. 본 궤적은 아직 재개하지 않았다.
비용 급증은 current 보조 행렬의 과도한 재구축이 지배했다. 전환 기준/재사용 간격 개선은 자료 조사만 했으며 미적용이다.
[원본·복구·병목 수치·전문 자료](../../experiments/R1_teacher_velocity_reset/timestep_search/evidence/three_scene_recovery_20260912/README.md). 아래 v2 준비 상태는 이전 기록이다.

확인 기준: 2026-09-12. 세 씬 10초 순차 실행 묶음 준비 완료, 본 계산은 시작하지 않았다.
기존 사각형·저장 삼각 깃발·손수건, 내부30% 목표/EW 상한1e-4·4배 dt를 사용한다.
사용자 수정 반영 v2: 첫 사각형만4시간 제한, 삼각 깃발·손수건은 시간 제한 없이600frame을 목표로 진행한다. 2.5초 수동 정지는 없다.
수치 실패/첫 씬 한도 종료는 보존하고 다음 씬으로 진행한다. 전체 wall time 상한은 없다.
구현: 동결 source/input·버전 검증, 순차 controller, 프레임 hi/lo 저장·재개, 단계 로그·실패 분모·비용 집계를 연결했다.
세 씬 GPU 원식 검산 통과, 재개 trace 차이0, 이전 CPU 검산 trace와 차이0, CPU5개 검사 통과(추가 두 씬의4시간 초과 진행 검사 포함).
[설정·명령·근거·미완료 범위](../../experiments/R1_teacher_velocity_reset/timestep_search/evidence/three_scene_batch_20260912/README.md). 기존 초기 연결의13개 검사는 선행 기록이다.
